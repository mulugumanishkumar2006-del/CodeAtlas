# CodeAtlas v1.2 Growth Scale & Infrastructure Bottleneck Model

This document models platform scaling for CodeAtlas across 4 growth tiers and identifies specific operational bottlenecks before scaling.

---

## 2. Infrastructure Bottleneck Analysis

### A. Database Connection Pool Limit (Tier C Constraint)
- **Constraint**: High concurrent REST requests exhausting default 20-connection PostgreSQL pool.
- **Remediation**: Deploy PgBouncer connection pooler in transaction mode with pool size set to 100.

### B. Neo4j Graph Memory Heap (Tier D Constraint)
- **Constraint**: Graph traversal traversals on 50M+ nodes exceeding 16GB RAM heaps.
- **Remediation**: Provision Neo4j Enterprise Cluster with read replicas and Cypher query depth caps (`MAX_DEPTH=4`).

### C. Celery Worker Queue Concurrency (Tier B Constraint)
- **Constraint**: Backlog when >50 repos queue simultaneous ingestion jobs.
- **Remediation**: Configure horizontal autoscaling Celery worker pools (`min=2`, `max=16` instances).

### D. AI Token Cost Protection (All Tiers)
- **Constraint**: Unbounded context window token usage on large monorepos.
- **Remediation**: Enforce strict context chunking (max 4,000 tokens per prompt) and semantic embedding caching.
