**STATUS: AI REASONING READY**

---

## 1. Architecture
CodeAtlas v1.2 evolves the system from basic AI question-answering into an evidence-grounded engineering intelligence platform. The architecture mandates that the deterministic engine (code AST, dependency graph, git history, impact intelligence) serves as the sole source of truth, while the AI engine explains, connects, evaluates, and reasons strictly over provided evidence.

```
USER QUESTION → INTENT CLASSIFIER → CONTEXT PLANNER → EVIDENCE PACK → TRUST & PROMPT INJECTION DEFENSE → REASONING PIPELINE → REASONING VALIDATOR → GROUNDED ANSWER & CITATIONS
```

---

## 2. Intent System
Supports 17 explicit engineering intents (`EXPLAIN`, `INVESTIGATE`, `TRACE`, `COMPARE`, `IMPACT`, `DEBUG`, `ROOT_CAUSE`, `ARCHITECTURE`, `DEPENDENCY`, `SECURITY`, `PERFORMANCE`, `TECHNICAL_DEBT`, `MIGRATION`, `CHANGE_PLAN`, `DOCUMENTATION`, `TESTING`, `CODE_REVIEW`). Intent confidence is calculated dynamically, with ambiguity handled gracefully without inventing requirements.

---

## 3. Context Planner
Selective retrieval strategy mapping intent to target evidence types. Avoids repository dumps by retrieving only direct code symbols, graph paths, history co-changes, and relevant test cases.

---

## 4. Evidence Pipeline
Assembles evidence items (ID, Type, Source, Location, Content, Confidence, Recency, Reliability). Ranks evidence using weighted directness scores ($Confidence \times Recency \times Reliability$) to ensure strong direct evidence overrides weak context.

---

## 5. Trust Boundaries
Repository content (code, comments, READMEs, commit messages, issue titles) is strictly treated as UNTRUSTED DATA.

---

## 6. Reasoning Contract
Every response enforces a standardized contract:
- `SUMMARY`
- `KNOWN FACTS`
- `EVIDENCE`
- `ANALYSIS` (6-stage structured sequence)
- `POTENTIAL IMPACT`
- `RISKS`
- `UNCERTAINTIES`
- `RECOMMENDATION`
- `VALIDATION STEPS`
- `SOURCES` (Clickable citations)

---

## 7. Claim Model
Claims are classified into 5 categories: `FACT`, `INFERENCE`, `PREDICTION`, `RECOMMENDATION`, and `UNKNOWN`. Unevidenced claims are automatically downgraded in confidence or flagged as unverified by the Reasoning Validator.

---

## 8. Root Cause Reasoning
Structured symptom-to-cause pipeline (`SYMPTOM` → `OBSERVATION` → `DEPENDENCY` → `CONSTRAINT` → `ROOT CAUSE` → `EVIDENCE` → `RECOMMENDATION`).

---

## 9. Impact Reasoning
Combines knowledge graph traversals with impact intelligence to forecast direct and transitive breakage risks.

---

## 10. Architecture Reasoning
Evaluates component coupling, structural boundaries, and interface erosion using code, graph, and historical co-changes.

---

## 11. Debugging
Collects stack traces, errors, recent commits, and test outputs to formulate likely causes, alternative hypotheses, and validation steps.

---

## 12. Security Reasoning
Analyzes auth flows, input boundaries, and secret usage using deterministic code analysis first. Enforces safe action recommendations.

---

## 13. Migration Reasoning
Produces staged migration plans with explicit dependency ordering, API contract compatibility checks, and rollback procedures.

---

## 14. Investigation State
Persists reproducible engineering investigation sessions (`investigation_id`, `question`, `hypothesis`, `evidence`, `findings`, `rejected_hypotheses`, `conclusion`, `validation_status`) scoped by tenant ID.

---

## 15. AI Provider Abstraction
Replaceable `LLMProvider` interface (Gemini, OpenAI, Mock) with automated retries, token limit enforcement, latency monitoring, and cost tracking.
